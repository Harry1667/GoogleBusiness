# 商家代管事業｜輔助工具 PRD

> **目的**：把 `9-talk.md` 裡的流程，從「靠紀律 + 試算表」升級為「工具自動化」，讓一個人可以同時管 30+ 個店家而不爆炸。
>
> **使用者**：我自己（單人創業者）。後期可能擴展到 2–3 人小團隊。
>
> **設計原則**：
> 1. **不過度工程**：能用試算表先做的，先不要寫程式
> 2. **AI 優先**：每一個耗時的工序都要有 AI 介入
> 3. **手機 + 電腦雙端**：拜訪用手機，後台用電腦
> 4. **MVP 先跑通，再優化**：第一版只做 P0，不做 P1/P2

## 2. 工具規格

---

### 🔴 P0-1｜業務隨身包 PWA

#### 痛點
- 拜訪時手忙腳亂，話術忘光
- 想滑 Before/After 給老闆看，要找半天
- 老闆問價格時要算半天
- 想當場簽同意書但要打字輸 LINE

#### 使用場景
- 走進店裡前：滑一下話術 + 異議處理
- 老闆有疑慮時：滑出對應的應對話術
- 老闆問成果：滑出 Demo 集
- 老闆問價：點兩下出報價單
- 老闆說好：一鍵把同意書發到 LINE

#### 功能清單
| 模組 | 功能 | 細節 |
|---|---|---|
| 話術速查 | 三段式話術全文 | 卡片式呈現，左右滑切換 |
| 異議處理 | 4 種老闆類型 + 5 大經典問題 | 點分類 → 出話術 |
| Demo 集 | Before/After 圖庫 | 可分類（餐飲 / 機車行 / 小賣店）、可全屏滑動 |
| 報價計算機 | 套餐 + 加值組合 | 滑桿 / 多選，即時算總價 |
| 同意書產生器 | 填空 → 出 LINE 訊息 | 一鍵複製 / 一鍵分享到 LINE |
| 拜訪紀錄 | 拜訪一家就記一筆 | 時間、店名、結果（成交/拒絕/再訪）、備註 |

#### 技術需求
- **平台**：PWA（手機開瀏覽器即用，可加到主畫面）
- **離線可用**：Service Worker 快取話術、Demo 圖
- **資料儲存**：IndexedDB（單機）/ Supabase（雲端同步）
- **不需要登入**：第一版單人用，密碼鎖前端即可

#### 驗收標準
- [ ] 從進店到滑出 Demo 圖 < 5 秒
- [ ] 報價計算 < 3 次點擊出結果
- [ ] 同意書產生 → 分享到 LINE < 10 秒
- [ ] 完全離線可用（除了 LINE 分享）

---

### 🔴 P0-2｜客戶 CRM（極簡版）

#### 痛點
- 試算表存客戶資料，但沒辦法看「現在哪個客戶該做什麼」
- 月代管收款日散亂，會漏收
- 哪個客戶下次該發什麼貼文記不住

#### 核心資料模型
```
客戶 (Client)
├─ 基本資料：店名、老闆姓名、電話、LINE ID、地址、業種
├─ 服務狀態：方案類型、簽約日、交付日、月代管起始日
├─ 收款：應收/已收清單、下次收款日
├─ GBP 資料：GBP 帳號 Email、後台連結、類別
├─ 內容歷史：已發貼文、已回評論
└─ 備註：老闆性格、特殊偏好、禁忌話題
```

#### 主要視圖
| 視圖 | 用途 |
|---|---|
| **今日待辦** | 「今天要發貼文的 3 家、要收款的 1 家、要交付的 1 家」 |
| **客戶列表** | 表格 + 篩選（狀態、業種、月代管 vs 一次性） |
| **客戶詳情頁** | 單一客戶的所有資料 + 歷史 |
| **本月收入** | 累計、預期、未收 |

#### 功能清單
- [ ] 新增 / 編輯 / 刪除客戶
- [ ] 標籤分類（業種、區域、狀態）
- [ ] 收款提醒（每月 1 號自動列出本月應收）
- [ ] 服務到期提醒（合約到期前 7 天提醒）
- [ ] 一鍵匯出 CSV（備份）
- [ ] LINE 通知 Bot：每天早上 8 點推播今日待辦

#### 技術需求
- **後端**：Next.js API Routes + Supabase / 自架 Postgres
- **前端**：Next.js 14 App Router + Tailwind + shadcn/ui
- **部署**：Docker → Oracle 鳳凰城（aaPanel + Nginx 反代）
- **驗證**：單人使用，先用 Basic Auth 即可

### 🔴 P0-3｜AI 內容工廠

#### 痛點
- 30 個客戶 × 4 則貼文 = 120 則 / 月，手寫會死
- 商家簡介每家都要重寫
- 評論回覆每次都要動腦

#### 核心功能

##### A. 商家簡介產生器
**輸入**：
- 店名 + 業種 + 主打品項 + 特色（3 個關鍵字）+ 區域

**輸出**：
- 3 個版本（活潑 / 專業 / 在地感）的 100 字內簡介
- 自動塞 5 個本地 SEO 關鍵字

##### B. 月度貼文批次生成
**輸入**：
- 選 1 個或多個客戶
- 月份、活動主題（節慶 / 開學 / 換季）
- 該店產品列表（從 CRM 帶入）

**輸出**：
- 每客戶 4 則貼文（活動 / 產品 / 在地連結 / CTA）
- 每則含：標題、內文、CTA 按鈕、配圖建議
- 可一鍵複製，或匯出為排程清單

##### C. 評論回覆助手
**輸入**：
- 貼上一則客戶評論 + 選擇店家
- 自動帶入該店家的「品牌語氣」設定

**輸出**：
- 5 星感謝版 / 4 星補強版 / 1–3 星滅火版三種語氣
- 100 字內，自然不油膩

##### D. 模板庫
- 自己常用的好話術可以「收藏」進模板庫
- 下次點兩下就能改

#### 技術需求
- **AI**：Claude API（claude-opus-4-6 寫貼文、claude-haiku-4-5 寫評論回覆省成本）
- **Prompt 管理**：所有 prompt 寫成 YAML / Markdown，方便調整
- **快取**：相同輸入快取 24 小時，省 token
- **成本控制**：每月設預算上限，超過自動暫停

#### 驗收標準
- [ ] 一次幫 10 個客戶生成本月 4 則貼文 < 3 分鐘
- [ ] 評論回覆生成 < 5 秒
- [ ] 月 API 成本 < NT$ 500（30 客戶規模）

### 🟡 P1-1｜客戶雷達

#### 痛點
- 手動掃 Google Maps 找客戶太慢
- 不知道哪家店「最值得」打

#### 核心功能
##### A. 區域掃描
- 輸入：地址 + 半徑（500m / 1km / 2km）+ 業種
- 抓取：Google Places API 列表
- 輸出：店家清單（名稱、類別、地址、評分、評論數、照片數）

##### B. 痛點打分
自動依以下指標計算 0–100 分：
| 指標 | 權重 | 說明 |
|---|---|---|
| 照片數 < 5 | +30 | 沒照片 = 大痛點 |
| 評論數 < 30 | +20 | 評論少 = 沒在經營 |
| 最近 3 個月無更新 | +20 | 後台沒人管 |
| 評分 3.8–4.5 | +15 | 甜蜜帶 |
| 無網站 | +10 | 完全沒數位資產 |
| 無 LINE 官方 | +5 | 補充資訊 |

##### C. 一鍵加入 CRM
- 勾選 → 一鍵把高分店家加到 CRM「待拜訪」狀態
- 自動帶入名稱、地址、電話

#### 技術需求
- **API**：Google Places API（有免費額度，超過收費）
- **替代方案**：Puppeteer + 抓 Maps Web 介面（注意 ToS）
- **預算控制**：每次掃描前顯示預估 API 成本

#### ⚠️ 風險
- Google Places API 有 ToS 限制，不能批次儲存超過 30 天
- 痛點分數要實際跑 50 家驗證，避免「分數高但其實搞不定」

### 🟡 P1-2｜月報生成器

#### 痛點
- 月底要寫 10–30 份月報，純手寫會崩潰
- 數據要從 GBP 後台一個一個截圖

#### 核心功能
##### A. 數據抓取
- **自動**：透過 GBP API（Google My Business API）抓取
  - 搜尋曝光、地圖曝光、路線、電話點擊、評論數
- **半自動 fallback**：老闆給後台權限後手動截圖上傳，AI OCR 讀數值

##### B. 月報生成
- 套用 `9-talk.md` 第 8 節的月報模板
- 自動計算月變化百分比
- AI 自動寫「本月亮點 + 下月計劃」段落
- 一鍵生成圖卡（Canva API / 自製 SVG）

##### C. 一鍵發送
- 生成完直接推到客戶 LINE / Email
- 標記「已送出」

#### 技術需求
- **GBP API**：要先申請 Google Business Profile API 權限（要驗證身份）
- **OCR**：Tesseract / Claude Vision（後者更準但要錢）
- **圖卡**：先用 HTML → puppeteer 截圖，省事

#### 驗收標準
- [ ] 30 份月報生成 < 30 分鐘
- [ ] 數據錯誤率 < 1%

---

### 🟢 P2-1｜交付看板

#### 痛點
- 同時交付 5 家客戶，每家進度不同，會搞混
- D1、D2、D3 任務不知道哪個做了哪個沒做

#### 核心功能
- 看板式 UI（類似 Trello / Linear）
- 每個客戶一張卡，依交付階段（D1–D7）拖曳
- 每張卡內含該日 checklist
- 完成 → 自動跳到下一階段

#### 技術需求
- 直接整合在主後台，不另外做
- 用 dnd-kit 或 react-beautiful-dnd

---

### 🟢 P2-2｜收款合約模組

#### 痛點
- 月代管 30 家，收款記錄散亂
- 退費 / 異動沒記錄會出包

#### 核心功能
##### A. 自動帳單
- 每月 1 號自動產生「本月應收清單」
- 推到 LINE 通知客戶
- 點擊 → 顯示付款方式（轉帳 / LINE Pay / 街口）

##### B. 對帳
- 手動標記已收 / 未收
- （進階）串接銀行 Open API 自動對帳

##### C. 合約存證
- 同意書版本管理
- 客戶簽收後存 PDF 上 S3 / Supabase Storage

## 3. 技術棧建議

### 推薦選型（依個人環境）
| 層 | 選型 | 理由 |
|---|---|---|
| 前端框架 | Next.js 14（App Router） | 全端一把刀，部署簡單 |
| UI | Tailwind + shadcn/ui | 快速、現代、可客製 |
| 後端 | Next.js API Routes | 不另外開後端服務 |
| 資料庫 | PostgreSQL（自架 Docker） | 配合 Oracle 鳳凰城環境 |
| ORM | Prisma / Drizzle | 型別安全 |
| 認證 | Lucia / Auth.js（單人先 Basic Auth） | 簡單夠用 |
| AI | Claude API（Anthropic SDK） | Opus 寫長文、Haiku 跑量 |
| 圖片處理 | Sharp + 外接 Photoroom API | 自架基本處理、AI 修圖外包 |
| 儲存 | MinIO（Docker）/ Cloudflare R2 | 省成本 |
| 排程 | node-cron / Supabase Cron | 月初帳單、貼文排程 |
| 部署 | Docker Compose → Oracle 鳳凰城 | 配合既有環境，aaPanel + Nginx 反代 |
| 監控 | Uptime Kuma | 自架免費 |
| LINE 通知 | LINE Notify / Messaging API | 業務通知 + 客戶月報 |

### 不要做的事
- ❌ 不要用微服務架構（單體就好）
- ❌ 不要用 Kubernetes（Docker Compose 就夠）
- ❌ 不要自己搞 LLM Fine-tune（用 Prompt Engineering 即可）
- ❌ 不要做手機原生 App（PWA 就夠）
- ❌ 不要做多租戶 SaaS（單人用，第二期再說）

## 6. 風險與假設

### 技術風險
| 風險 | 緩解 |
|---|---|
| GBP API 申請被拒 | Fallback 到截圖 + OCR |
| Google Places API 太貴 | 限制單次掃描範圍、加快取 |
| Claude API 漲價 / 限流 | 同時支援 Gemini / OpenAI 切換 |
| 自架伺服器掛掉 | Uptime Kuma 監控 + 每日異地備份 |

### 業務假設（要驗證）
- ⚠️ **假設 1**：手動跑通流程後，工具能讓我管 30+ 客戶 → 第一個月驗證
- ⚠️ **假設 2**：店家老闆願意讓我代管後台 → 第一週驗證（如果不願意，整個商業模式要重想）
- ⚠️ **假設 3**：AI 生成的內容品質能讓老闆滿意 → 第二週驗證

### 不做工具的條件
**如果以下任一情況發生，先不要寫工具，先解決商業問題**：
- 第一個月成交數 < 3 家 → 是商業問題，不是工具問題
- 客戶都不願意給後台權限 → 商業模式要調整
- AI 生成內容老闆都嫌爛 → Prompt 要先調好再做工具
